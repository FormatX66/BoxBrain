# Help Build Aurum

You do **not** need to be a programmer to help Aurum.

This page is the starting point for friends, family, testers, researchers, writers, hardware people, and developers who want to contribute.

## Fastest way to join

1. Create or sign in to your own GitHub account: https://github.com/signup
2. Open the Aurum helper form: https://github.com/FormatX66/BoxBrain/issues/new?template=aurum-helper.yml
3. Pick the kinds of help you are comfortable with.
4. Submit the form.
5. The Aurum GitHub automation will reply with the next steps.

That is enough to join. You do not need repository write access, a development environment, or a paid account.

## Ways to help

### No coding required

- Try Aurum and describe what worked or failed.
- Test instructions on a normal Windows computer.
- Test Raspberry Pi or other hardware you already own and are authorized to use.
- Rewrite confusing documentation in plain English.
- Find missing steps, broken links, spelling mistakes, and unclear buttons.
- Research a technical question and attach sources.
- Suggest simpler user flows or UI improvements.
- Reproduce a bug and write down the exact steps.

### Coding and technical help

- Fix a small bug.
- Add or improve tests.
- Improve PowerShell, Python, Flutter, or automation code.
- Review a pull request.
- Investigate a failing GitHub Action.
- Improve local-first or resumable Aurum build behavior.

## Safe contribution model

New helpers should normally contribute through issues, forks, and pull requests rather than receiving direct write access to the main branch. This keeps Aurum easy to help without making the project fragile.

Never post passwords, API keys, private tokens, Wi-Fi credentials, personal files, or other secrets in an issue, pull request, log, screenshot, or test result.

Only test on computers, accounts, networks, and hardware that you own or are explicitly authorized to use.

## If GitHub feels confusing

Start with the helper form and choose **I am not sure — give me something easy**. The automation will point you toward a beginner-safe contribution path.

## For contributors making changes

Read the repository-level [CONTRIBUTING.md](../../CONTRIBUTING.md) before opening a pull request. GitHub will also insert the project's pull request checklist automatically when you submit changes.
