# Change Log

## BrainConnect

- **Changed files:** Controller operation models, SQLite schema, operation API,
  policy metadata, health response, plugin discovery model, backend tests,
  Flutter API client, operation model and forms, dashboard status, widget
  tests, open-lab plugin manifest, and canonical documentation.
- **Reason:** Establish a truthful, durable capability-first queue before
  connecting live execution to the disposable VM.
- **Dependencies:** Enabled target identity, persistent emergency stop,
  append-only audit storage, Flutter dashboard, and clean VM checkpoint.
- **Future implications:** The adapter can consume a stable typed queue without
  redesigning the UI or persistence layer. Adding execution requires a result
  state machine, external credentials, bounded evidence, and target/session
  correlation.

## BoxBrain

- **Changed files:** Admin indexes, roadmap, master TODO, repository index,
  system architecture, data flow, BrainConnect project index, project table,
  and this session bundle.
- **Reason:** Preserve the direction change, implementation revision, decision,
  verification evidence, and next execution plan in the single source of
  truth.
- **Dependencies:** BrainConnect commit `155b526` and draft pull request 8.
- **Future implications:** Capability-first control is now the active
  BrainConnect milestone; observation-only frames remain documented but are no
  longer the immediate next step.
